Before any mechanism, get the map. LLM security is the overlap of three things people often
conflate:

- **Safety** — the model avoiding harmful *content* (the model's own behavior).
- **Security** — protecting the *system* around the model (data, tools, accounts, weights).
- **Misuse prevention** — stopping a determined person from getting *capability* the
  provider chose to withhold.

A guardrail can serve one of these and do nothing for the others. Keeping those apart is
half of thinking clearly here.

## The vocabulary

The terms below recur throughout. Precise use of them is what separates a useful security
conversation from a vague one.

- **Guardrail / safeguard** — any control that constrains model behavior. Umbrella term.
- **Alignment** — training the model to *want* to behave well (M3). A property of the model.
- **Moderation / classifier** — a separate system that screens inputs or outputs (M12).
- **Jailbreak** — getting the model to violate its *own* policy (M7).
- **Prompt injection** — untrusted content hijacking the model's instructions (M4, M8).
- **Misuse** — using the model for harm it will *willingly* help with absent safeguards.

:::note[Jailbreak ≠ prompt injection]
A jailbreak is the *user* tricking the model into breaking its rules. Prompt injection is a
*third party's* text (in a document, a web page, a tool result) doing it. Different attacker,
different trust boundary, different defense. The course keeps them separate.
:::
