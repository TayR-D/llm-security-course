"Why doesn't the model just refuse?" hides a wrong assumption: that refusal is a rule
somewhere in the code. It isn't. Refusal is a **learned behavior**, added in stages during
training, and like everything learned it's a strong tendency rather than a guarantee. Knowing
which stage adds which property tells you exactly where each attack (and each defense) applies.

## The key consequences

- **The base model will answer almost anything.** Pretraining builds capability, not
  refusal. Everything protective comes later — which is why an open-weight model with its
  alignment fine-tuned away is so different from the same weights behind an API (M9, M17).
- **Refusal generalizes imperfectly.** RLHF and Constitutional AI push refusal beyond the
  hand-written examples, but "mismatched generalization" — the model generalizing capability
  more broadly than it generalizes refusal — is exactly the seam jailbreaks exploit (M7).
- **The policy source is a document.** Modern alignment optimizes against an explicit spec or
  constitution. That same document often trains the runtime classifiers too (M11, M12), which
  is why a provider's written policy is worth reading closely.
- **Safeguards you can update without retraining live outside the weights.** That's the whole
  point of the deployment layer (M10) — and the reason it can't protect a downloaded model.
